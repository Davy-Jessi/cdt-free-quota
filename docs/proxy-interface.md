# 代理侧：需要遵守的接口约定

> ⚠️ **先读 [`../DISCLAIMER.md`](../DISCLAIMER.md)。** 本仓库的通常用途被阿里云服务条款
> 明文禁止（ECS《使用须知》：禁止流量穿透，违规最高关停并锁定实例并清退）。
>
> **本文档不教怎么搭代理。** 它只写清楚：**守护（本仓库提供的那部分）对代理侧有哪些要求。**
> 代理用什么软件、怎么配置，由你自己决定并自担后果。

---

## 一、为什么只给接口

守护（`cdtguard.py`）与代理是**两个独立的东西**：

```
┌─────────────────────────────────────────┐
│  ECS 实例                                │
│  ┌───────────────┐   ┌────────────────┐ │
│  │ 代理（你的）   │   │ cdtguard（本仓库）│ │
│  │ 监听端口、转发 │   │ 计量 + 到阈值停机 │ │
│  └───────┬───────┘   └────────┬───────┘ │
└──────────┼────────────────────┼─────────┘
           │                    │
           ▼                    ▼
      网卡 → EIP → 共享带宽包（计费在这里）
```

**守护不认识代理，代理也不该认识守护。** 两者唯一的耦合点是「公网流量从同一个出口走」。

所以本文档只写**三条硬约定** —— 违反任何一条，守护就失效。

---

## 二、三条硬约定

### 1. 公网出口必须是**被计量的那一个**

守护的计量口径是**共享带宽包 + 网卡**，也就是「从这台机器出去的公网流量」。

**不能做的**：

- 让代理从**另一条**出口出去（第二张 EIP、另一个 NAT 网关、隧道到别处）
  —— 那些流量**不在这台机器的网卡上**，守护看不见，**会静默超额**
- 走云企业网 / 对等连接把流量导到别的地域 —— 那是**跨地域流量**，是另一套计费项

**判据**：如果在代理满速跑的时候，守护日志里的 `纯网卡acc` 不涨，就是出口接错了。

### 2. 代理必须能在**实例被停机再拉起后自己恢复**

守护到阈值时会 **`ForceStop` 停机**（强制关机，不是优雅关机）。

**不能做的**：

- 代理依赖**内存里的临时状态**（会话、动态生成的配置）—— 硬关机后全丢
- 代理**没有设开机自启** —— 实例被 FC 拉起后它不会自己回来
- 配置文件在上次运行时被改过、但**没落盘**

**判据**：受控重启一次（`rc-service cdtguard restart` 或手工重启实例），
确认代理**自动**回来了，且客户端不用改配置就能用。

### 3. 代理不能绕过网卡直接发包

不能做的：raw socket 直接驱动网卡、SR-IOV 直通、或者任何让流量**不经过内核网络栈**的手段。

理由同第 1 条 —— 守护靠 `/proc/net/dev` 读网卡计数，**绕过内核的流量它读不到**。

## 三、带宽怎么设才不会超预算

这是最容易出事的地方。**守护到阈值才停机，而「停机」不是瞬时的**：

```
最坏超出量 ≈ 轮询间隔 × 当时峰值带宽
```

守护的轮询间隔是 **2 秒**（`INTERVAL`），云监控口径还有 **170~300 秒**的滞后。

| 峰值带宽 | 2 秒能跑多少 | 300 秒能跑多少 |
|---:|---:|---:|
| 100 Mbps | 25 MB | 3.7 GB |
| 800 Mbps | 200 MB | **30 GB** |
| 1000 Mbps | 250 MB | 37 GB |

**所以**：

- **阈值 200 GB 等于免费额度本身，余量为 0。** 触发时计费侧正好到 200 ——
  上面那张表的「超出量」全都要自己付。
- **想留余量**：改部署后的 `/root/cdtguard.py`，把 `THRESHOLD_ENV` 那一行设成
  `"185"`（留 15 GB）。⚠️ **环境变量对 `supervise-daemon` 托管的进程无效** ——
  它启动时会清空子进程环境，所以只能改文件（见 `scripts/cdtguard.initd`）。
  或者**把峰值带宽调低**。
- **不要为了跑得快把带宽拉满**。峰值越高，最坏超出量越大，而**超出部分按阶梯价付费**。

> ⚠️ **共享带宽包有一个计费陷阱**：按带宽计费时取「**当日最大带宽峰值**」——
> 当天把峰值调高，**全天按高的收**。而且**不足 1 小时按 1 小时**。
> 开了 23 秒就删掉，仍被收满 1 小时（¥14 量级）—— **删包不能止损**。
> 详见 [`pitfalls.md`](pitfalls.md) 第 3 条。

## 四、出账自查

守护的计量是**推算**，账单才是**权威**。至少核对一次：

| 查什么 | 在哪 |
|---|---|
| CDT 累计用量 | 控制台 → 云数据传输 → 公网明细账单（单价为 0 或阶梯为 0 的那部分就是免费额度） |
| 免费额度是否真的抵扣 | 同上：若额度内的流量**有金额**，说明计费方式选错了（见 [`billing.md`](billing.md)） |
| 超额了多少 | 账单里阶梯价那部分 |
| 有没有"不该有"的费用 | 共享带宽包的按带宽计费、EIP 保有费、函数计算的小时最低消费 |

**守护自身的口径核对**：它的日志里每 10 分钟打一行

```
HYBRID base=NN.NNNNGB lag=NNN.Ns | 纯网卡acc=NN.NNNNGB 混合=NN.NNNNGB 差=+N.NN%
```

- `base` = 云监控（计费侧）读数
- `纯网卡acc` = 网卡累加
- `混合` = 守护实际用的值（`base` + 网卡补最近几分钟的增量）
- `差` = 网卡口径相对计费侧的**结构性偏高**。代码里的口径是 **约 +5%**
  （`cdtguard.py` 里 `BW_UNDER_PCT = -2.0` / `BW_OVER_PCT = 30.0`：
  低于 −2% 就告警，高于 +30% 才算异常）。**它会随流量形态浮动**，
  低负载时更小 —— 所以别把 +5% 当固定值，**看方向和量级**即可。

**若 `差` 变成负数，说明网卡少算了 —— 那是危险方向，要查。**

---

## 五、一句话

**守护只保证一件事：它看得见的流量不会超。**

所以你要保证的是：**所有计费流量都让它看得见**（走同一个出口、过内核网络栈），
**而且停机之后你的服务能自己回来**。
