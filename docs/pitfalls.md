# 踩坑清单

**每条都有证据，但来源不同**：一部分是真实踩过的损失与故障，
另一部分是官方规则的引用（没有事故，但有出处）。逐条看下面的证据分级，别一概而论。

| 标注 | 含义 |
|---|---|
| **【官方】** | 有阿里云文档原文，附链接或 doc_id，可直接核验 |
| **【控制台】** | 阿里云控制台页面上的原文或提示。帮助文档里**查不到**，只能靠控制台页面或截图核验 |
| **【实测】** | 本机观测，**只对本机成立，不要当平台规则用** |
| **【推断】** | 逻辑推出，未验证 |

## 一、会烧钱的（按严重度排）

### 1. 🔴 共享带宽的 `InternetChargeType` **默认值是错的**

**【官方】** 中国站取值为 `PayByBandwidth`（**默认值**）/ `PayBy95` / `PayByDominantTraffic`。

**省略这个参数 = 拿到按带宽计费的共享带宽 = 吃不到 CDT 免费额度，还按小时烧钱。**

必须显式写 `PayByDominantTraffic`（按主流量计费）——**只有它能用免费额度**。

### 2. 🔴 `ISP` 必须保持 `BGP`

**【官方】** 「仅 **BGP（多线）** 类型的公网流量具有免费额度，**BGP（多线）_精品类型不具有免费额度**」。

选成 `BGP_PRO` 精品线路，一分额度都用不上。

> ⚠️ 原文「**仅中国香港地域支持包年包月的 BGP（多线）_精品线路**」容易被误读成
> 「香港只支持精品线路」。**两者意思相反**，而这个误读会直接推翻整个方案的前提。

### 3. 🔴 按带宽计费：**不足 1 小时按 1 小时**

**【官方】** 「如果持有时长不足 1 小时，按 1 小时计算」。

建了一个按带宽计费的共享带宽包，**23 秒后删掉，仍被收满 1 小时（¥14 量级）**。

原文里还有一个「15:10:23 创建、16:08:33 释放、按 2 小时计」的示例，
说明计费按**小时向上取整**。

### 4. 🔴 按增强型 95 计费有**最短持有期**——比固定带宽更毒

**【官方】** 「选择增强型 95 计费模式**至少需要使用一个自然月，且一个自然月内无法删除**，
最早能在下个月的 1 号及之后删除」。

**一个误操作就是一个月的支出，且当天退不掉。**

### 5. 🟠 函数计算有**每小时最低消费**——与调用量无关

**【官方】** 「针对单小时内调用次数 > 0 或者持续占有计算资源的函数，
每小时消耗 CU 折算金额**若低于 0.01 元，将按 0.01 元计费**」。

**【实测】** 日账单里**调用数相差数倍，而 CU/小时恒定 100**（≈¥0.011）。

**所以：费用 = ¥0.011 × 「有调用的小时数」。**
8 分钟一次、30 分钟一次、59 分钟一次——**成本完全相同**；只有跨过小时才有差别。

> ⚠️ **「¥0.011」这个单价会变。** 官方对 CU 发过限时折扣（2024-08-27 ~ **2026-08-27** 那档
> 折扣价 ¥0.000088/CU，比目录价 ¥0.00011/CU 低 20%）——**打折期间 100 CU 只有 ¥0.0088**，
> 低于 ¥0.01 的最低消费线，于是按 ¥0.01 收，月成本是 **¥7.2 而不是 ¥7.9**。
>
> 🔴 **那个窗口已经在 2026-08-27 到期，且截至 2026-09-30 未见续期公告**
> （官方价目页 9 月重新发布过，活动时间仍是原来那一段）。
> **所以现在按目录价算：¥7.9/月 才是当前的数**，而「官网常态打折」这个说法已不成立。
> **要用的时候自己拿当期单价重算一遍**，别把本仓库的这个数当长期有效。

> ⚠️ 「与调用次数、执行时长完全无关」**只在最低消费区间成立**。
> 官方触发条件是「折算金额低于 0.01 元」，超了按实际 CU 计。

### 6. 🟠 闲置 EIP 持续计费——但**别为了省钱去解绑**

**【官方】** 「按量付费的 EIP 在创建后、未绑定任何资源时，会持续产生 **EIP 配置费（公网 IP 保有费）**」。

**【官方】** 同时写明：**直接绑定到 VPC 类型的 ECS 实例或 ECI 实例**（且账号 EIP **配额** ≤ 2000，
注意是配额不是实际持有量）时免收。

**所以正确做法是「让它一直绑着」，而不是「不用时解绑」**——解绑会立刻开始产生保有费，
并同时打断服务。

### 7. 🟠 配额：按主流量计费只有 **10 个/账号/地域**

**【官方】** 「每个账号每个地域最多可持有的按量计费共享带宽实例的数量：
按带宽计费方式 **5 个** / 按增强 95 计费方式 **5 个** / **按主流量计费方式 10 个**」，
提升方式是「**请联系您的商务经理**」——**不是工单**。

### 8. 🟠 两个接口都**没有 `DryRun`**

**【官方】** `CreateCommonBandwidthPackage` 的参数表里**没有 `DryRun`**；
`AllocateEipAddress` 同样没有。

**「先 DryRun 试一下」这条退路不存在。**

### 9. 🟡 不可逆清单

| 操作 | 为什么不可逆 |
|---|---|
| **升级至 CDT 计费** | **【控制台】** 升级页面正文「升级之后**不支持回退**」（⚠️ 帮助文档里**没有**这句；出处与截图见 [`billing.md`](billing.md) 第四节），且【官方】「**所有存量和新增的**按流量计费实例」都会切过去——**影响账号上所有按流量业务** |
| 购买包年包月共享带宽 | 【官方】「在当前合同期内，只支持升配，**不支持降配和释放**」 |
| 抢占式实例 `Terminate` | 【官方】连**系统盘一起释放**；且**实例中断模式创建后不可修改** |
| 释放 EIP | 不保证能取回同一个 IP |
| 领取 FC 新客试用 | 一次性资格，「同一用户仅能对同一产品申请试用一次」 |

## 二、计量口径（守护为什么容易失效）

### 10. 🔴 云监控数据点**滞后 170~300 秒**

**【实测】** 多次采样落在 **174~300 秒**之间，**会波动**。

例：按 800 Mbps 满速算，3.7 分钟 ≈ **22 GB 盲区** —— 你的带宽不同，这个数按比例变。
**所以云监控不能单独当闸门。**

### 11. 🔴 云监控数据点的**时间戳语义**：标注的是区间**结束**时刻

**【实测】** 小时级点标注 `T` 覆盖的是 **`[T-1h, T)`**；分钟级同理。

**对齐证据**：取某一小时的**分钟级积分**求和，与**小时级**该点标注的值**完全相等**
（即小时级点标注的是一个**已走完的区间**）。

> 曾按「标注 = 区间开始」写成 `t + 3600000 > now 就跳过`，
> 于是把最近一个**已走完**的整小时误判成「当前小时」丢弃，改用分钟级去估——
> **实测少算约 0.6 GB**。

### 12. 🟠 刚结束的那个小时**聚合值仍在形成中**

**【实测】** 17:00:12 就把「17:00」这个点当成已结算纳入，结果
(a) 金额少算 (b) 覆盖时刻被报成整点 → 桥接窗口被压到 12 秒 → 合计少算。**方向危险。**

**对策**：整点后留 5 分钟结算余量（`BW_SETTLE_MIN`）。

### 13. 🟠 网卡口径**结构性偏高**，且偏高是**安全的**

网卡按 `Σmax(每次采样)` 累加，计费按 `max(Σ整小时)`，数学上恒有 `Σmax ≥ max(Σ)`。

**【实测】** 偏高约 **+5%**（曾误报过 48%——那是取数时间戳 bug 造出的假象）。

**所以偏差告警必须是单向的**：偏高是预期行为，**偏低才危险**（说明网卡少算）。
写成 `abs(dev)` 必然误报。

### 14. 🟠 比较必须用**同一时刻的快照**

计数量每 2 秒刷新、计费量每 600 秒刷新。拿实时值去比会随计费量变旧而**单调放大**——
纯属跨新鲜度比较的假象。（曾因此每 10 分钟误报一条。）

### 15. 🟡 免费额度是**账号级**的，会和账号上其他业务抢

**【官方】** 「免费额度按阿里云账号维度计算（而不是按实名认证用户维度）」；
「同一实名认证用户名下的多个阿里云账号可分别独立享受各自的免费额度池」。

**所以「这 200 GB 是这台机器的」这个心智模型是错的。**

> ⚠️ 后半句还意味着：**多开账号能各拿一份额度**。但阿里云对「同一用户」的判定
> 覆盖「同一证件、同一手机号、同一支付账号、同一设备、同一登录环境」——
> **不要为了放大额度去多开账号。**

## 三、守护设计（fail-open 是最危险的模式）

### 16. 🔴 「拒绝启动」往往比「带着旧值启动」更糟

如果守护因为取不到配置而拒绝启动，在 `supervise-daemon` 下就是
**每 5 秒重启一次 → 无限 crash-loop，期间完全无计量、无护闸**，
而且告警代码在 `main()` 里，**连告警都发不出去**。

**这是拿小风险换大风险。**

### 17. 🔴 停机判定**不能**依赖「查实例状态」

旧设计是 `if 实例状态 == "Running": 停机`。那是个 fail-open：
实例 ID 过期时查到的是**旧实例**，若它处于 Stopped，整个停机块被跳过，**流量继续烧**。

**根本认识：守护运行在这个实例内部，代码能执行 = 实例必然 Running。**
状态查询在语义上是多余的，**绝不能当安全闸门**。

### 18. 🔴 一个不存在的实例 ID **不会报错**

**【实测】** `DescribeInstances` 查一个不存在的 ID → **HTTP 200 + TotalCount 0 + 空数组**，
不是错误。

所以「查不到 → 返回 None → 跳过停机」这条路径**完全静默**：
只有一行日志每 2 秒重复，流量继续烧。

（对比：`StopInstance` 对不存在的 ID **会**报 `InvalidInstanceId.NotFound`——两者行为不同。）

### 19. 🟠 `StopInstance` 的两种失败要区别对待

| 错误码 | 含义 | 应该怎么处理 |
|---|---|---|
| `404 InvalidInstanceId.NotFound` | ID 不存在 | **判为配置错误 → 响铃** |
| `403 IncorrectInstanceStatus` | 当前状态不支持（即已 Stopped） | **判为成功**（幂等语义），不告警 |

**否则会把「已经停了」误报成失败。**

### 20. 🟠 停机必须 `ForceStop`，且在停机**之前**发推送

本实例用自制精简镜像，镜像内无阿里云代理组件，优雅关机指令投递不进 guest——
实例会**永久卡在 Stopping**（实测 >2 分 39 秒），而进程仍在跑、流量仍在烧。
**强制关切实测几秒完成。**

而 `ForceStop` 会**立刻杀死本进程**，停机之后的任何代码都不会执行——
**所以「停机成功」的推送必须由外部（FC）发出。**

### 21. 🟠 日志与状态必须 `fsync`

硬关机时 guest 的脏页会被丢弃。日志恒 `fsync`；状态按**字节**决定是否 `fsync`，
这样硬关机后的「少算量」才有上界。

状态的临时文件名必须**带 PID**——固定名会并发互踩。

### 22. 🟡 状态文件的缺省值必须是 `None` 而不是 `0`

整机重建后本地状态文件不存在，会从远端状态恢复。若远端状态缺字段而缺省给 `0`，
主循环会把**整个网卡计数器**当成一轮增量，**凭空多算几个 GB，可能直接误触发停机**。

**那比 KeyError 更糟：崩溃是响的，静默多算才致命。**

## 四、部署与运维

### 23. 🔴 `supervise-daemon` 会**清空子进程环境**——`/etc/conf.d/<svc>` 无效

**【实测】** 服务定义用 `supervisor="supervise-daemon"` 时，
写 `/etc/conf.d/<svc>` **传不进环境变量**：实测 python 进程的
`/proc/<pid>/environ` 里只剩 `HOME PATH PWD SHLVL USER` 一类的变量。

**如果没验就上「缺环境变量即退出」的守护，就是无限 crash-loop。**

### 24. 🟠 元数据服务读取必须做两个防护

**【实测】** 代码里的坑，但适用于任何读 `100.100.100.200` 的场景：

1. **必须用空 `ProxyHandler`** —— `urllib` 默认读 `http_proxy`/`HTTP_PROXY`。
   哪天环境里加了 proxy，元数据请求会被送去代理、返回错误页。
   **这个故障只在元数据这一处爆出来，极难查。**
2. **必须 `.strip()`** —— 元数据返回值带 `\r\n`。不 strip 会让实例 ID 变成 `"i-xxx\r\n"`，
   拼进请求后报 `InvalidInstanceId.NotFound`——**等于亲手制造一个静默 fail-open。**

### 25. 🟠 函数计算的 `environment_variables` 是**整体覆盖**语义

**【官方】** `UpdateFunction` 时漏一个键 = 删一个键。

**所以必须 `Get` → 原样合并 → `Update`，绝不硬编码清单。**
漏掉一个凭据键就是 FC 全线静默失效。

### 26. 🟠 `UpdateFunction` 之后**热实例可能仍跑旧代码**

**必须调用一次并断言返回的 `ver` 等于源码里的常量**，否则会在
「以为部署成功、实际跑旧代码」的状态下收工。

### 27. 🟡 简版发行版的 busybox 工具不可信

**【实测】** 在 Alpine 上：

- `ss` 会**漏报**监听端口——查端口用 `netstat`，或加 `nc -z` 交叉验证
- `ls --time-style=...` 不支持，**加了参数整个 `ls` 无输出**（不报错）
- `pgrep -f <pattern>` 对正在运行的进程返回空

**「工具没输出」不等于「目标不存在」。** 先确认工具本身可信，再下结论。

### 28. 🟡 账单里的 CDT 字段名变了——**不代表免费额度变了**

**【官方】** 自 **2026-05-20** 起 CDT 升级至 2.0（doc_id `3029446`）：
账单里的商品 Code 从 `cdt_internet_public_cn` / `cdt_cdtir_public_cn` 变为
`cdt_DataTransfer_public_cn`，计费项从 13 个按云产品拆分的名字
（`ECS_Out_Bytes`、`Eip_Out_Bytes`、`Cbwp_Out_Bytes` …）精简为
`internet_traffic` / `inter_region_traffic`。

**【官方】原文明确：「目录价、免费额度、阶梯定价规则和资源包均保持不变」，
「账单金额不会发生变化」**，且升级**由后端自动完成，无需手动操作**。

**陷阱在于**：新账号**默认就是 2.0**。若照老名字去账单里找 CDT 计费项，
会**找不到** —— 从而误判成「CDT 没生效」或「这套方案在新账号上不适用」。

**守护不受影响**：它读的是用量接口 `ListCdtInternetTraffic`，**做的是分组求和** ——

```python
sum(x.get("Traffic", 0) for x in d.get("TrafficDetails", []))
```

它**从不读** `ProductTrafficDetails[].Product`（那个字段连提都没提过）。
所以某个产品被改名、被合并进别的条目，**求和结果都不变** —— 2.0 碰不到它。

> ⚠️ 顺带说清这个接口的文档状态：它**没有公开文档**（CDT 不在 OpenAPI 产品目录里），
> 返回结构是【实测】来的。详见 [`billing.md`](billing.md) 第六节。

**所以：在账单里看到陌生字段，不要据此改代码。**
详见 [`billing.md`](billing.md) 第五节。

## 五、工具与操作

### 29. 🔴 浏览器自动化会把**已登录控制台**的页面树落到磁盘（含账号 UID）

**【实测】** 用 Playwright MCP 打开 `home.console.aliyun.com` 后，工作目录下会出现
`.playwright-mcp/`，其中 `page-*.yml` 是**页面的无障碍树快照** ——
里面含 **16 位阿里云账号 UID**。实测踩到，而且该目录**当时没被 gitignore**。

**为什么这对本仓库特别要紧**：`console/*.md` 正是让 agent 去控制台导航和截图的。
只要它用浏览器自动化，就会生成这个目录 —— 一次 `git add -A` 就进了公开仓库。

**两道防线都要有：**

- 把 `.playwright-mcp/` 写进 `.gitignore`（本仓库已加，见文件里的说明）
- 截图**只截元素、不截整页** —— 整页会带上顶栏的账号名与账号 ID

**【实测】** Playwright 的 `locator.screenshot()` 可以只截内容区，自然排除顶栏。
**但提交前务必自己看一眼图。** 本仓库那两张控制台截图也验过：
PNG 只含 `IHDR`/`IDAT`/`IEND`，无 `tEXt`/`iTXt`/`eXIf` 文本夹带。

> 📌 **PNG 元数据检查要连二进制一起扫** —— 文本夹带不一定出现在肉眼可见的
> 图像内容里。一行 `identify -verbose` 或直接看 chunk 列表即可。
> 但**「无文本夹带」只解决元数据这一半**：截图**内容**里的账号信息要靠遮罩，
> 且遮罩不是自动的 —— 本仓库的做法是只截内容区 + 手工遮住状态/操作列。
